# The 2026 — 2030 Stack

> Branch-stable systems for the next half-decade of building.

The mainstream consensus is the 2022 stack on autopilot: Next.js, Vercel, Supabase, Clerk. It works. It is also the past dressed in 2026's clothes.

This document is the alternative. Three use cases — landing pages, product web apps, mobile apps — engineered for solo founders and small elite teams targeting the 2026 to 2030 window. Visionary where the trajectory justifies it. Boring where boring wins. Always honest about which is which.

---

## 0 / Manifesto

Three words have been cheapened by marketing and need redefinition before any pick makes sense.

### 0.1 / What "edge" actually means

True edge is code executing inside a V8 isolate or WASM sandbox in the same point of presence that terminates the user's TLS connection. Cold start measured in 0.5 to 10 milliseconds, not 100 to 500.

By that strict definition, four platforms qualify in 2026:

`Cloudflare Workers + Durable Objects` — V8 isolates across 330+ PoPs.
`Fastly Compute@Edge` — Wasmtime, mature, niche mindshare.
`Fermyon Wasm Functions on Akamai` — Spin runtime, CNCF, 0.5ms cold start.
`Fly.io Machines` — Firecracker microVMs with anycast. Edge-shaped non-edge: VMs are heavier, but any language runs.

Vercel Fluid Compute is regional Lambda with smart routing. Deno Deploy Classic is shutting down July 20, 2026. AWS Lambda multi-region is multi-region Lambda. Calling these "edge" is marketing.

### 0.2 / What comes after edge

A round trip to a 5ms-away PoP is still 5ms. The frontier is local-first sync engines that put the authoritative read path **inside the client process**. Zero round trips for reads. Optimistic mutations for writes. Sync in the background.

Linear, Figma, Superhuman proved the UX delta for a decade. The tooling to do this without hand-rolling a CRDT layer just shipped:

`Rocicorp Zero` — sync engine over vanilla Postgres, ZQL queries client-side.
`ElectricSQL 1.0` — Postgres-to-anywhere sync, GA March 2025.
`Turso libSQL` — SQLite at the edge with embedded replicas.
`Convex` — reactive backend with built-in optimistic updates.

The edge becomes the write path and authority. The client becomes the read path. This is the architecture shift of the decade.

### 0.3 / What ownership means

Ownership in 2026 is three things, not one.

**One:** the data lives in vanilla open-source primitives that can be self-hosted (Postgres, SQLite, a self-owned auth schema), not a proprietary cloud database.

**Two:** the framework has a Plan B runtime. Hono runs on Cloudflare, Bun, Deno, Node, Fastly, AWS Lambda. Phoenix runs anywhere Erlang runs. Workers can be self-hosted on `workerd`.

**Three:** authentication is OSS and self-hostable. Clerk, Auth0, Supabase Auth — all are vendor-locked rentals on someone else's user table.

`Better Auth` — $5M from Peak XV / Y Combinator, June 2025. Auth.js team merged in.
`Hanko` — passkey-first, fully OSS.

These are the answer. The mainstream picks are not.

## 1 / Use Case — Landing Pages

> Marketing sites, content-heavy. SEO-critical. Fast iteration. Zero-JS-by-default.

### 1.1 / The pick

`Astro 6` + React or Solid islands → `Cloudflare Workers` (static + Server Islands) → `Better Auth` if gated → `Drizzle` + `Neon` if dynamic.

Astro 6 (beta, early 2026) ships the Vite Environment API and a `workerd`-based dev server with full prod parity. Cloudflare acquired the Astro Technology Company on January 16, 2026; framework remains MIT.

Server Islands cache the HTML shell at every PoP and surgically defer dynamic personalized blocks. Zero JS by default. Lighthouse 100, every time, no exceptions. View Transitions ship with zero JS where browsers support them.

### 1.2 / Why not Next.js 16

Next.js 16 (October 21, 2025) is excellent for product apps now that Cache Components replaced App Router's "magic caching," Turbopack is stable as the default bundler (2 to 5 times faster builds, up to 10 times faster Fast Refresh), and React 19.2 ships with it.

But for a marketing landing page, Next.js ships ~40 KB of React runtime baseline whether wanted or not. Astro ships zero. For a landing page, "ship zero JavaScript" is the killer feature. Full stop.

### 1.3 / The hypermedia alternative

For a content site with rich real-time updating sections — pricing tables, live availability, AI-personalized hero — there is a more visionary pick:

`Go + Templ + Datastar v1` on Cloudflare Workers or Fly Machines.

Datastar is an 11.8 KB hypermedia framework — htmx and Alpine merged, SSE-first, signals-based, stable at v1.0.1. Carson Gross's HTMX is the spiritual predecessor. Datastar is what HTMX wanted to be when it grew up.

If the landing page is mostly text and images, pick Astro. If it has rich server-driven dynamism without a full SPA shape, Datastar is correct.

### 1.4 / 3-to-5 year risk + escape hatch

Astro is now Cloudflare-owned. Mostly upside (deeper Workers integration), nominal lock-in optics. Astro builds to standard `.html` + JS bundles. If Cloudflare's strategy shifts, redeploy to Netlify or Vercel in an afternoon. Framework is MIT. Output is web standards.

## 2 / Use Case — Product Web App Where the Landing Page *is* the App

> Linear, Figma, Notion, Vercel itself, Compass, Pacaso. The same codebase serves anonymous SEO-grade marketing *and* post-login interactive UI.

This is where the consensus is most wrong, and where the visionary 2026 answer most diverges. There are two correct picks depending on temperament. Both are defensible. Neither is "Next.js + Supabase + Clerk."

### 2.1 / Pick A — The Sync-Engine Stack

**Genuinely future-looking. TypeScript end-to-end. Ownership-first.**

`TanStack Start` (RC) + `Rocicorp Zero` + `Neon Postgres` + `Better Auth` + `Hono` + `Cloudflare Workers (+ Hyperdrive)` + `Drizzle`.

#### TanStack Start (RC, November 2025)

Built on TanStack Router + Vite + Nitro. Type-safe React meta-framework that respects engineering intelligence. Selective SSR per route. Server functions. Deploys to Cloudflare, Netlify, Node, Bun unchanged.

After early v1.x perf bottlenecks, TanStack Start became the *fastest* of the three frameworks tested in Platformatic's 1000-req/s SSR benchmark. The right React framework for engineers who want explicit data flow.

#### Rocicorp Zero (approaching beta, late 2025 / early 2026)

The read/write sync engine that solves "the round trip is the latency bottleneck."

Works with existing Postgres schema. Exposes ZQL — SQL-shaped queries — on the client. Normalizes results into client-side IndexedDB. Instant local resolution with server fallback.

Zero 0.23 (October 2025) added synced queries, custom mutators, first-class React Native. Funded maintainers — Aaron Boodman and Erik Arvidsson, ex-Dropbox/Google, builders of Replicache. Productlane and others run it in production.

Status check: approaching beta, not GA. Use for products where the UX delta justifies the maturity risk. Skip for compliance-critical apps.

#### Neon Postgres

Right pick despite — actually because of — the Databricks acquisition for ~$1B in May 2025. Compute pricing dropped 15-25% post-acquisition; storage ~80%. Branching is O(1). Scale-to-zero is real (not Aurora Serverless v2 fake-real). Open source. Escape hatch is `pg_dump` to vanilla Postgres on Fly MPG, RDS, or self-hosted.

#### Better Auth

Owns the user table inside the team's own Postgres. TypeScript-native. Plugin architecture. Auth.js team merged in. $5M seed from Peak XV / Y Combinator. 150K+ weekly downloads, 15K+ stars at funding. Self-hostable; managed dashboard is opt-in.

The single most important pick on this list for ownership. Clerk holds the users. Better Auth lets the team `pg_dump` them.

#### Hono

The framework everyone converged on for edge runtimes. Multi-runtime: Workers, Deno, Bun, Node, Fastly, Lambda. Cloudflare itself uses Hono internally for D1, Workers Logs, and KV. Tiny. Type-safe RPC built in.

#### Cloudflare Workers + Hyperdrive

Workers for the Hono backend. Hyperdrive in front of Neon for global connection pooling and query caching. Right pattern in 2026: Postgres central, Hyperdrive distributed, Workers everywhere.

#### Drizzle

The only TypeScript ORM that genuinely works on edge runtimes. ~7.4 KB. No native binaries. First-class Neon, D1, Turso adapters. Prisma 7 finally works on edge but is heavier and pushes toward Accelerate.

#### When this stack is correct

Marketplaces. Real-estate platforms. Productivity tools. Any "list / filter / detail" product where read-side instant interaction (Linear-tier UX) is the differentiator. SEO-friendly via TanStack Start SSR for unauthenticated routes. Zero handles read sync. Hono handles writes through Workers. Better Auth handles sessions. Neon is source of truth.

### 2.2 / Pick B — The Server-Rendered Reactive Stack

**Boring-but-genuinely-visionary. Bet a five-year company on this if starting fresh today.**

`Phoenix 1.8` + `LiveView 1.1` + `Fly.io Machines` + `Fly Managed Postgres`.

#### The pitch in one sentence

All the interactivity of an SPA, with server-rendered HTML diffs over WebSockets, in 350 lines for a typical app, with no JS bundler, no client cache to invalidate, no GraphQL schema, no tRPC.

LiveView 1.0 shipped December 3, 2024. 1.1 added portals, colocated hooks, JS.ignore_attributes. Phoenix 1.8 shipped August 5, 2025 with streamlined generators and OTP 25+ baseline.

Sponsored by Fly.io (Chris McCord works there) and Dashbit (José Valim's company). Highly funded maintainers. Decade-plus track record. Deployed at scale by Discord, Heroku, Mozilla, Pinterest, X.

People migrate from React to LiveView and report LiveView client rendering is *faster* than their React app was.

#### Deployment

Fly.io Machines — Firecracker microVMs, anycast routing — with Fly Managed Postgres (GA 2025, $0.28/GB/month storage). Multi-region with `fly-replay` for write routing to primary region and read replicas in every region. App and DB co-located in the same Firecracker host. Sub-millisecond intra-region latency.

#### Auth

`mix phx.gen.auth` generator. No third party. Done in 30 seconds.

#### The unfair advantage — LiveView Native

The same Elixir LiveView serves web UI *and* a fully native iOS / iPadOS / visionOS / macOS / watchOS app via SwiftUI, *and* an Android app via Jetpack Compose, from one codebase.

LiveView Native 0.4 RC ships SwiftUI and Jetpack clients in early 2026. DockYard's analysis: ~40% time / cost reduction vs separate React + Swift teams.

Collapses a three-platform team into one. Single biggest leverage point for a solo founder building a serious mobile + web product. The genuinely visionary pick that most TypeScript-founder bubbles ignore.

#### Risk + escape hatch

Elixir hiring market is smaller than TypeScript. The community is famously high-caliber — formerly Rails refugees and BEAM specialists. For a solo founder hiring themselves, this is a non-issue.

Plan B if Phoenix flames out: it won't. The BEAM has been in production for 40 years powering telecoms and WhatsApp. LiveView is a 6-year-old battle-tested abstraction on top.

### 2.3 / Verdict between A and B

For a top-tier solo TypeScript founder building an AI product → **Pick A** (TanStack Start + Zero + Neon + Better Auth + Hono + Workers).

For someone open to leaving the TypeScript bubble for a 5-to-10× productivity win → **Pick B** (Phoenix + LiveView + LiveView Native + Fly.io). Phoenix has Dashbit + Fly.io behind it. Not amateur territory.

### 2.4 / Why not Convex

Convex is excellent. $24M Series B from a16z + Spark in November 2025. Open-source backend. Production-grade. Best DX of any reactive backend.

The reason it's not the primary pick: it ties the codebase to a custom transactional engine and TypeScript on the server. For an ownership-conscious founder who wants Plan B that runs anywhere, vanilla Postgres + Zero is more portable. Convex is Plan B's Plan A.

If business logic is heavily reactive and portability is irrelevant: Convex over the entire stack above. Genuinely.

### 2.5 / Why not Supabase

Supabase Realtime piggybacks on Postgres logical replication — wrong primitive for fine-grained UI sync. Supabase Auth is fine but not as ownable as Better Auth. Supabase is a great product. It is not the *visionary* product. It is the Heroku of 2018: solid, well-loved, mainstream.

### 2.6 / Why not Aurora DSQL

Aurora DSQL went GA in late May 2025. Genuinely serverless. Distributed. Multi-region active-active. PostgreSQL-compatible. Real engineering achievement.

But: AWS-only (lock-in). Opaque DPU pricing. Optimistic concurrency requires app-level retry logic. No triggers, foreign keys, stored procedures yet. Right pick for a publicly-listed company in 2027. Wrong pick for a solo founder in 2026.

## 3 / Use Case — Mobile App

> Native UX, offline support, push notifications, smooth animations, in-app purchases.

The Expo + RN answer is correct *but boring*. The visionary answer depends on what's being optimized.

### 3.1 / Pick A — Maximum velocity, minimum risk

`Expo SDK 55` + `RN 0.83 New Arch`.

Expo SDK 55 shipped January 2026 with React Native 0.83, React 19.2, the New Architecture as mandatory and non-disable-able (Legacy Arch frozen June 2025), Expo Router v7, brownfield isolation via `expo-brownfield`, Hermes Bytecode Diffing (75% smaller OTA updates), and built-in MCP / agent skills tooling.

83% of EAS Build SDK 54 projects are already on New Arch as of January 2026. Platform is mature. New Arch performance is finally near-native (JSI, Fabric, TurboModules eliminated the bridge). Expo Router v7 has guarded route groups and synchronous layouts.

Stack:
`Expo` + `Expo Router v7` + `React Query` + `Zero (RN client)` + `Better Auth` + `Hono backend on Workers` + `Neon` + `RevenueCat`.

#### RevenueCat is non-negotiable

State of Subscription Apps 2026: 115K+ apps, $16B+ revenue, 1B+ transactions. Subscription apps launching at 14,700 per month in January 2026 — 7× growth since 2022. 31% of Android churn is now billing failure, not user intent.

RevenueCat raised $50M Series C from Bain Capital Ventures in May 2025. Moving toward web payments now that the Apple-Epic ruling permits external links. 2026 testing showed adding a web purchase button retains ~93¢ per IAP dollar (vs 30% Apple cut) where applicable.

Use it from day zero. Building IAP is a known mistake.

### 3.2 / Pick B — Maximum code reuse with truly native UI

`Phoenix LiveView Native`.

For founders who chose Pick B for the web. iOS and Android targets for free. SwiftUI and Jetpack Compose render real native components. Business logic and state management is Elixir on the server, sent as diffs over WebSocket.

LiveView Native 0.4 RC is shipping in early 2026. Honest community read late 2025: SwiftUI client is real and shippable; Jetpack Compose client lags by ~6 months but is funded and progressing.

This is the genuinely visionary pick. Whether it's right depends on willingness to leave React Native.

### 3.3 / Pick C — The dark horse for Kotlin teams

`Compose Multiplatform 1.8+`.

Shipped May 6, 2025, marking iOS as Stable. Native scrolling physics, native text editing, native drag-and-drop, full accessibility (VoiceOver, AssistiveTouch). CMP 1.10 promoted Compose Hot Reload to stable, added Navigation 3 on non-Android targets.

Forbes, Netflix, H&M, Bilibili in production. JetBrains-backed — the company that *makes IntelliJ*. Funding floor is iron-clad. Swift Export targeted for stable in 2026 to enable idiomatic Kotlin↔Swift interop without the Objective-C bridge.

For a TypeScript founder, too far afield. For a founder with Kotlin / Android background, this beats RN on every dimension that matters except hiring market.

### 3.4 / Pick D — Don't bother

`Tauri 2` / `Dioxus`.

For a "mobile app" that is really a wrapped web view with some camera or notification integration. Tauri 2 (Rust shell, web frontend) and Dioxus (Rust, single codebase web/desktop/mobile). Tiny binaries, native performance. iOS story is still maturing in 2026.

Don't pick these for a serious consumer app yet. Pick them for an indie tool.

### 3.5 / Verdict for mobile

For 95% of solo founders shipping in 2026 → **Pick A** (Expo SDK 55).
For founders who chose Pick B for web → **Pick B** (LiveView Native), with Expo as escape hatch if Jetpack client lags.

## 5 / Hot Takes

**One.** Vercel is the IBM of the modern web stack. Excellent for enterprise teams with budget. Stop calling Fluid Compute "edge" — it is regional Lambda with smart routing. Deploying the same Next.js app to Cloudflare Workers via OpenNext saves ~70% of the bill and gains real edge.

**Two.** Supabase + Clerk is the 2022 default stack on autopilot. Both are great products. Both are also vendor lock-in. Better Auth + Neon delivers 100% of the feature set, ownership of the user table, and Plan B = `pg_dump` to anywhere.

**Three.** React Router v7 is fine. Remix v3 is research. Don't start a new app on either. **TanStack Start is the right React meta-framework for new code in 2026** unless Vercel-flavored magic is specifically required, in which case Next.js 16 with eyes open about cache complexity.

**Four.** The "edge" race is over and Cloudflare won. Deno Deploy Classic is shutting down July 20, 2026. The new Deno Deploy is down to 6 regions. Fastly Compute@Edge is technically excellent but has lost developer mindshare. Fermyon Wasm Functions on Akamai is the dark horse for polyglot WASM at edge but is still niche. **Cloudflare Workers + Durable Objects + R2 + D1 + Workers AI + Hyperdrive + Containers is the only complete edge platform.**

**Five.** Local-first sync engines will be the default for productivity apps by 2027. Zero, ElectricSQL, Convex, Turso embedded replicas, PowerSync, InstantDB, Triplit, Replicache. Pick one. The round-trip-eliminated UX is a step-change visible to end users (Linear vs Jira; Superhuman vs Gmail). Ignoring this layer in 2026 is the equivalent of ignoring SPAs in 2014.

**Six.** Phoenix LiveView + LiveView Native is the most underrated stack of the decade for solo founders. The cross-platform code reuse story — *one Elixir codebase to web + iOS + Android with truly native rendering* — has no equivalent in the JS world. The Elixir hiring market is small but high-caliber. A solo founder is hiring themselves.

**Seven.** Bun is the new Node, but not yet for production runtime. Use Bun as bundler / test runner / package manager *now*. Use as production runtime cautiously — memory leaks in long-running processes are still a real complaint as of April 2026. The Anthropic acquisition (December 2025) puts the funding floor at Anthropic-tier. Production-runtime ready by SDK 56 / Bun 1.4.

**Eight.** Drizzle wins over Prisma for the next decade. SQL-first. Edge-native (~7.4 KB, no native binaries). First-class adapters for Neon / D1 / Turso. Prisma 7's edge story is finally OK, but its bundle and Engine binary still cost cold-start time on Workers / Lambda.

**Nine.** HTMX / Datastar is not a joke. For the right product (server-state-heavy, low-interactivity, content-heavy with sprinkles of dynamic), Datastar at 11.8 KB + Go templ + Cloudflare Workers will outperform a React SPA by every measurable metric and ship 5× faster. Most products aren't that product. Some are. Be honest about which.

**Ten.** Astro winning the content-site war is decided. Cloudflare's acquisition. Server Islands. View Transitions. Live Content Collections in Astro 6 close the gap with dynamic frameworks while keeping zero-JS-by-default. Stop using Next.js for marketing pages.

**Eleven.** PlanetScale is back from the dead with Postgres support but doesn't matter for solo founders. It's an enterprise pick with an enterprise price tag now. Neon + Hyperdrive eats its lunch for everything below $50K/mo in DB spend.

**Twelve.** Convex is excellent and not the primary recommendation, which says something. $24M Series B from a16z + Spark in November 2025. Open source. Production-grade. Best DX of any reactive backend. The reason it's Pick A's runner-up: vanilla Postgres + Zero gives the same UX with zero proprietary infrastructure. If portability is irrelevant: Convex over the entire stack.

**Thirteen.** Effect-TS is the right pick for AI agent infrastructure. Production-ready. Used by Vercel, Markprompt, Glide, Zendesk. For functional-programming-flavored type safety with proper error / dependency management on the API / agent layer, this is where serious teams are going. Steep learning curve.

**Fourteen.** Gleam is interesting but not yet right for most projects. v1.0 in March 2024. Growing fast. Statically typed BEAM language. Production stories are mounting but ecosystem is still maturing. Watch it. Don't bet on it for a 2026 startup.

**Fifteen.** Loco.rs ("Rails for Rust") is real but for a specific kind of person. Inspired by DHH's "one-person framework." Runs on Axum + SeaORM + sidekiq-rs. For founders who love Rust *and* want Rails-shaped productivity. Most TypeScript-native founders should not switch.

## 6 / Cost

> What it takes to run each stack. Two stages: dev, scale.

Dev means one builder, internal testers, light traffic. Scale means soft launch through 100K MAU, multi-region production. Numbers are USD per month, infrastructure only. Stripe is broken out separately because it dominates and obeys different physics.

### 6.1 / Per-stack ranges

| Stack | Dev | Scale (100K MAU) | What drives the bill |
|---|---|---|---|
| **Use Case 1 — Astro Landing** | `~$0` | `~$200` | Email volume past Resend free tier. Sentry / PostHog past free tiers. R2 storage for assets. |
| **Use Case 2A — TS Sync Engine** | `~$15` | `~$2,000` | Neon compute hours and Postgres storage. Durable Objects WebSocket activity (40× difference between hibernating and active). Sentry + PostHog event volume. Self-hosted Zero infrastructure. |
| **Use Case 2B — Phoenix Server-Rendered** | `~$50` | `~$2,800` | Fly Managed Postgres (always-on, no scale-to-zero floor at $38). Multi-region machine count. AP-region egress at 2× US/EU rate. |

Stage transitions happen on three trigger lines, not on calendar dates.

**Dev → Soft Launch.** Email volume crosses the Resend free tier (3K/mo). Sentry crosses 5K errors/mo. Database compute starts running 24/7. Infrastructure exits free tiers and lands at `~$30–60/mo`.

**Soft Launch → Scale.** PostHog crosses 1M events/mo. Sentry needs the Business plan. Database compute scales beyond a single CU. Real-time / sync traffic becomes the variable cost. Workers requests cross 10M/mo.

### 6.2 / Stripe is the line item that matters

| MRR | US merchant (`2.9% + $0.30`) | TH merchant (`3.65%` + FX stacking) |
|---|---|---|
| `$10K` | `~$300/mo` | `~$370/mo` |
| `$100K` | `~$2,950/mo` | `~$3,650/mo` |
| `$1M` | `~$29,500/mo` | `~$36,500/mo` |

The `$7K/mo` delta at $1M MRR is bigger than every other line item combined. Stripe Atlas — Delaware C-Corp, `$500` one-time, `~$300/yr` ongoing — closes it on day one.

Founders outside the US who skip incorporation pay a hidden tax of `~$90K/yr` at $1M MRR. The infrastructure stack is rounding error against this number.

### 6.3 / RevenueCat at scale

For subscription apps. `1%` of MTR above the `$2,500/mo` floor. At `$250K MTR` (typical 100K MAU subscription app at ~5% conversion × ~$5 ARPU): `~$2,475/mo`. At `$2.5M MTR`: `~$24,975/mo` — negotiate enterprise pricing past `$1M MTR`.

RevenueCat applies identically to Use Case 3A, 3B, and 3C. It is not a stack-selection variable.

### 6.4 / What drives the bill

Five components dominate every stack in this document.

**Database compute.** Neon scales to zero. Fly MPG floors at `$38/mo` always-on. The economics of Neon dominate at <50% utilization. Fly MPG fixed pricing wins at ~24/7 100% utilization.

**Real-time WebSocket activity.** Cloudflare Durable Objects published example: 100 DOs × 100 hibernating WebSockets = `~$10/mo`; same DOs × 50 active WS broadcasting = `~$138/mo`; 100 DOs serving 1 WS/sec full month = `~$416/mo`. Use the WebSocket Hibernation API or pay 40×.

**Observability event volume.** Sentry + PostHog combined cross from `~$26/mo` at 10K MAU to `~$600–1,500/mo` at 100K MAU to `~$5,000–7,000/mo` at 1M MAU. Super-linear. Sample aggressively.

**Asset egress.** Cloudflare R2 charges `$0` egress in all regions. Vercel charges `$0.40/GB` past included bandwidth. At 1 TB/mo overage: `$400/mo` saved by being on Cloudflare.

**Payment processing percentage.** Linear with revenue. Cannot be optimized except by incorporation jurisdiction and merchant of record selection.

### 6.5 / Three numbers

`$5/mo` — practical floor for a real Cloudflare Workers + R2 production stack.

`$38/mo` — practical floor for Fly Managed Postgres on the Phoenix path.

`2.9% vs 3.65%` — the difference Stripe Atlas makes for a non-US founder. Above `~$120K/yr` GMV the `$500` Atlas fee pays for itself in the first month.

## 8 / Final Word

The corrective to the mainstream stack is not adopting every shiny pre-1.0 framework. That's amateur hour.

The corrective is recognizing that the real 2026-2030 trajectory is four shifts:

**One.** Sync engines eliminating the edge round-trip for the read path.

**Two.** Vanilla Postgres + OSS auth as the durable storage / identity layer that survives any vendor implosion.

**Three.** V8 and WASM at the actual edge for the write path and globally distributed compute.

**Four.** Server-rendered reactive frameworks (Phoenix LiveView, with HTMX / Datastar for hypermedia-pure cases) as a serious alternative to SPA bloat that finally has the funded maintainers and 1.0 stamps to be safe.

For a real-estate-tier product built today as a solo founder with AI ambitions and ownership obsession:

`TanStack Start` + `Hono` + `Cloudflare Workers` + `Hyperdrive` + `Neon` + `Drizzle` + `Better Auth` + `Rocicorp Zero` + `Workers AI` + `Expo SDK 55` + `RevenueCat`. Marketing site: `Astro 6 on Workers`.

Alternate path for those willing to leave the TypeScript bubble:

`Phoenix` + `LiveView` + `LiveView Native` + `Fly.io`.

Single most leveraged stack for a one-person team in 2026.

The rest is noise.
